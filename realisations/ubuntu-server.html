Serveur de test pour applications internes

Mise en place d'un serveur Ubuntu de test pour héberger des applications internes, avec Nginx en reverse proxy devant Node.js.

Contexte

Dans le cadre de mon stage BTS SIO SISR, l'entreprise avait besoin d'un environnement de test séparé de la production pour valider les évolutions d'applications internes avant leur mise en ligne définitive. J'ai mis en place et configuré ce serveur de A à Z.

Objectifs

  • Installer et configurer un serveur Ubuntu dédié à l'environnement de test
  • Déployer les applications internes avec Node.js
  • Mettre en place Nginx comme reverse proxy devant l'application
  • Garantir un environnement stable, isolé de la production

Fonctionnement

  • Installation d'Ubuntu Server et mise à jour du système
  • Installation de Node.js et déploiement de l'application interne
  • Configuration de Nginx en reverse proxy : redirection des requêtes, gestion des en-têtes et des noms de domaine
  • Utilisation de PM2 comme gestionnaire de processus (redémarrage automatique, démarrage au boot)
  • Tests de bon fonctionnement avant validation par l'équipe

Ce que ça m'a apporté

  • La configuration d'un serveur Linux de test complet, de l'installation à la mise en service
  • La compréhension du rôle d'un reverse proxy en production
  • La gestion de processus applicatifs avec PM2
  • Une meilleure autonomie sur l'administration système Linux

Améliorations possibles

  • Mettre en place un certificat SSL/TLS (Let's Encrypt)
  • Automatiser le déploiement avec un script ou un pipeline CI/CD simple
  • Ajouter une supervision de l'usage des ressources (CPU/RAM)
